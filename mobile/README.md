# GiftFinder для Android

Мобильный интерфейс использует тот же поисковый движок, фильтры, каталог,
курсы, избранное и локальный кеш, что и настольное приложение. Для телефона
используется отдельная компоновка; Windows-интерфейс в APK не растягивается.

[Предварительный ARM64 APK](https://github.com/Misha20062006/giftfinder/releases/download/v0.7.1-android.1/GiftFinder-0.7.1-Android-arm64-v8a.apk)
предназначен для Android 9+. Он подписан постоянным ключом проекта и
работает с обычными сетевыми источниками. Физический ARM64-телефон и
живой поиск на всех площадках пока не проверены.

## Сборка

Официальный `pyside6-android-deploy` работает на Linux и macOS. В CI
используется Ubuntu, Python 3.12, JDK 17, Android SDK/build-tools 35 и NDK
28c (`28.2.13676358`). Android-приложение запускается с Python, собранным
закреплённой версией python-for-android, и PySide6 6.12.0.

Скрипт этого проекта требует Linux x86_64 для закреплённого SDK и
пересборки Android-плагина Qt; это требование к сборочному компьютеру.

Точные версии, SHA-256 официальных Qt/PyPI wheels, исходники тонкого модуля
Shiboken и флаги линковки закреплены в `mobile/android-build-inputs.json`.
Чистые Python-зависимости устанавливаются из проверенных универсальных wheels:
вложенные ускорители Linux не переносятся в Android. Тонкий модуль
`shiboken6/Shiboken.abi3.so` генерируется из исходников той же Qt 6.12.0
и пересобирается NDK для настоящего ELF-выравнивания 16 КБ; изменение одного
заголовка ELF не используется.

Android-плагин Qt `libplugins_platforms_qtforandroid_<ABI>.so` также
пересобирается из QtBase 6.12.0 с точным SDK той же версии. В нём перенесены
две строки [официального исправления QTBUG-146706](https://github.com/qt/qtbase/commit/59e4671814e9e25e316ed7ec1fe3e5d276141914):
проверка доступности использует существование окон вместо ошибочного счётчика
поверхностей. Удаление всплывающего меню больше не скрывает главный экран от
Android accessibility. Обработчики Back и жизненного цикла приложения ради
этой ошибки не меняются. Остальные Qt/PySide библиотеки берутся из официальных
Android wheels.

Сборка плагина: `tools/android_qt_platform.py` и
`mobile/qt_platform/CMakeLists.txt`. SHA-256 исходников, исходного и
изменённого файла, SDK и готового плагина сохраняются в свидетельствах сборки;
версии и входы закреплены в `mobile/android-build-inputs.json` и входят в
fingerprint кеша. Исходные лицензии Qt сохраняются; см. `THIRD_PARTY_NOTICES.txt`.

```sh
python tools/build_android.py build --arch arm64-v8a
python tools/build_android.py build --arch x86_64 --smoke
```

Скрипт загружает Android wheels с сервера Qt и проверяет их SHA-256.
В отдельный staging-каталог попадают только отслеживаемые Git файлы
приложения, каталога, изображений, переводов и лицензий. Профиль пользователя
не копируется. Официальный инструмент генерирует рецепты Qt; затем скрипт
добавляет Python-зависимости, ресурсы и разрешение `INTERNET` в Buildozer.

`python tools/build_android.py cache-key` выводит fingerprint совместимости
нативного кеша. Он учитывает версии, SHA зависимостей, рецепты и флаги;
изменение этих входов выбирает отдельный distribution. Изменение интерфейса
не требует повторной компиляции неизменённого нативного runtime.

Приложение имеет ID `org.giftfinder.giftfinder`. Профиль находится во
внутреннем каталоге приложения Android, который возвращает Qt. Доступ к
Telegram-сессии, кошельку и системному хранилищу для поиска не нужен.

## Подпись и обновления

APK подписывается постоянным закрытым ключом. Для локальной сборки нужны
переменные окружения `GIFT_FINDER_ANDROID_KEYSTORE`,
`ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS` и `ANDROID_KEY_PASSWORD`.
В GitHub Actions keystore передаётся через секрет `ANDROID_KEYSTORE_BASE64`,
остальные три значения — через одноимённые secrets. Закрытый ключ и пароли
никогда не входят в исходники, APK, артефакты проверки или вывод команд.

Смена ключа нарушает возможность обычного обновления установленного APK;
используйте тот же keystore для последующих версий. Этот процесс не
публикует приложение в Google Play.

## Что проверяет CI

- ARM64 APK для телефонов: упаковка ресурсов и зависимостей, ID и launcher,
  отсутствие debug-флага, подпись и SHA-256. Все вложенные ELF, включая
  Python bundle, проверяются на архитектуру и Android-зависимости;
  ELF LOAD/RELRO и ZIP-выравнивание для 16 КБ проверяются отдельно.
- Отдельный x86_64 APK с офлайн-режимом для эмулятора: установка, запуск,
  маркер готовности интерфейса, сохранение процесса после запуска,
  отсутствие Python/Android crash в логе, отрисованные главная и фильтры,
  Back для всплывающих меню и списка категории, прокрутка языков пальцем,
  отрисовка после поворота с доступной кнопкой фильтров. Используется образ
  Android 15 `google_apis_ps16k`; перед запуском требуется `getconf PAGESIZE = 16384`.
- В том же явно включённом режиме проверки: Python SSL, SQLite и рабочий
  charset-normalizer, Qt TLS, HTTPS-загрузка неизменяемого публичного PNG
  из GitHub проекта через QtNetwork с обходом кеша, проверкой SHA и декодирования.
  Это проверка сетевого транспорта, а не доказательство доступности api.changes.tg.
- В том же режиме: обычное меню «Экспорт CSV», системный DocumentsUI,
  сохранение одной явно синтетической строки через `content://` и проверка
  точного содержимого чтением через QFile. Обычная ARM64-сборка не включает
  офлайн-режим и не запускает эти дополнительные проверки.

Офлайн-APK для эмулятора не предназначен для обычного поиска и не заменяет
проверку ARM64 APK на физическом телефоне. Проверка сборки также не
подтверждает доступность всех живых площадок из конкретной сети.
