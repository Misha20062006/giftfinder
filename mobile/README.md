# GiftFinder для Android

Мобильный интерфейс использует тот же поисковый движок, фильтры, каталог,
курсы, избранное и локальный кеш, что и настольное приложение. Для телефона
используется отдельная компоновка; Windows-интерфейс в APK не растягивается.

[Предварительный ARM64 APK](https://github.com/Misha20062006/giftfinder/releases/tag/v0.7.0-android.1)
предназначен для Android 9+. Он подписан постоянным ключом проекта и
работает с обычными сетевыми источниками. Физический ARM64-телефон и
живой поиск на всех площадках пока не проверены.

## Сборка

Официальный `pyside6-android-deploy` работает на Linux и macOS. В CI
используется Ubuntu, Python 3.12, JDK 17, Android SDK/build-tools 35 и NDK
28c (`28.2.13676358`). Android-приложение запускается с Python, собранным
закреплённой версией python-for-android, и PySide6 6.12.0.

```sh
python tools/build_android.py build --arch arm64-v8a
python tools/build_android.py build --arch x86_64 --smoke
```

Скрипт загружает Android wheels с сервера Qt и проверяет их SHA-256.
В отдельный staging-каталог попадают только отслеживаемые Git файлы
приложения, каталога, изображений, переводов и лицензий. Профиль пользователя
не копируется. Официальный инструмент генерирует рецепты Qt; затем скрипт
добавляет Python-зависимости, ресурсы и разрешение `INTERNET` в Buildozer.

Приложение имеет ID `org.giftfinder.giftfinder`. Профиль находится во
внутреннем каталоге приложения Android, который возвращает Qt. Доступ к
Telegram-сессии, кошельку и системному хранилищу для поиска не нужен.

## Подпись и обновления

APK подписывается постоянным закрытым ключом. Для локальной сборки нужны
переменные окружения `GIFT_FINDER_ANDROID_KEYSTORE`,
`ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS` и `ANDROID_KEY_PASSWORD`.
В GitHub Actions keystore передаётся через секрет `ANDROID_KEYSTORE_BASE64`,
остальные три значения — через одноимённые secrets. Закрытый ключ и пароли
никогда не входят в исходники, APK, артефакты проверки или вывод команд.

Смена ключа нарушает возможность обычного обновления установленного APK;
используйте тот же keystore для последующих версий. Этот процесс не
публикует приложение в Google Play.

## Что проверяет CI

- ARM64 APK для телефонов: упаковка ресурсов и зависимостей, архитектура,
  ID и launcher приложения, отсутствие debug-флага, подпись, выравнивание
  нативных библиотек для страниц 16 КБ и SHA-256.
- Отдельный x86_64 APK с офлайн-режимом для эмулятора: установка, запуск,
  маркер готовности интерфейса, сохранение процесса после запуска,
  отсутствие Python/Android crash в логе, отрисованные главная и фильтры,
  системная кнопка Back, отрисовка после поворота с доступной кнопкой фильтров.
- В том же явно включённом режиме проверки: Python SSL и SQLite, Qt TLS,
  загрузка одного изображения из публичного каталога по HTTPS через QtNetwork
  с обходом кеша и проверкой декодирования изображения.
- В том же режиме: обычное меню «Экспорт CSV», системный DocumentsUI,
  сохранение одной явно синтетической строки через `content://` и проверка
  точного содержимого чтением через QFile. Обычная ARM64-сборка не включает
  офлайн-режим и не запускает эти дополнительные проверки.

Офлайн-APK для эмулятора не предназначен для обычного поиска и не заменяет
проверку ARM64 APK на физическом телефоне. Проверка сборки также не
подтверждает доступность всех живых площадок из конкретной сети.
