Как устроен поиск GiftFinder 0.6

Приложение — Python + PySide6 / Qt Widgets, с обычными окнами Windows. Встроенного браузера, Chromium и WebView нет. HTTP-клиент requests получает HTML и JSON; BeautifulSoup разбирает HTML. Интерфейс Qt получает готовые записи и обновляет карточки.

1. Что происходит после нажатия «Показать»

Поиск сначала переводится в точные условия SearchQuery: коллекция, модели, фон, узор, номер, площадки, монохромность и цвета. Каталог содержит имена моделей, их принадлежность коллекциям, фоновые палитры и проверенные подборки. Выбор широкой темы или цвета разворачивается в список конкретных моделей, сгруппированных по коллекциям. Например, «чёрные монохромки по всем коллекциям» — это запросы по 100 заранее отобранным моделям из разных коллекций, а не поиск слова black в названиях.

Сразу читается локальная база SQLite market-cache.sqlite3. Ранее найденные подходящие объявления показываются с пометкой сохранённых данных. Затем фоновая задача обновляет выдачу из сети. GUI не ждёт синхронно завершения всех запросов.

2. Fragment: прямой HTML-парсинг

Для коллекции запрашивается GET https://fragment.com/gifts/{collection}. Передаются filter=sale, сортировка и поддерживаемые условия attr[Model], attr[Backdrop], attr[Symbol], номер. Из HTML читаются карточки a.tm-grid-item, статус For sale, ссылка и цена. Страница проверяется на правильную коллекцию и режим продажи: неожиданная страница не считается достоверным пустым ответом.

Если модель, фон и узор подарка уже известны, используются сохранённые характеристики. Иначе читается публичная страница https://fragment.com/gift/{slug}: таблица атрибутов, редкость модели и наличие кнопки Buy for. Это чтение страницы: покупка не создаётся и кнопка не нажимается.

Следующая страница определяется по data-next-offset. Приложение читает адрес публичного search API из страницы и посылает POST method=searchAuctions с offset_id. Хотя метод HTTP — POST, операция только читает результаты поиска. Временная HTTP-сессия существует для конкретного обхода; cookies и временные адреса API не записываются в профиль. После обхода сессия закрывается.

3. Portals: прямой JSON

Из https://portal-market.com/api/collections берётся соответствие названий коллекций внутренним идентификаторам площадки. Затем GET https://portal-market.com/api/nfts/search получает объявления с параметрами collection_ids, filter_by_models, filter_by_backdrops, filter_by_symbols и сортировкой.

Страница содержит до 50 записей. После полной страницы запрашивается следующая с offset + 50. Из результата извлекаются цена, модель, фон, узор, номер и ссылка на конкретное предложение мини-приложения. Пакеты из нескольких подарков не включаются: приложение ищет отдельные подарки. Вход в аккаунт для текущего публичного чтения не используется.

4. Telegram, Getgems, MRKT, Tonnel: индекс browse.tg

Для этих четырёх источников сейчас нет отдельных прямых подключений. Используется GET https://browse.tg/api/listings. Этот внешний сервис уже собирает предложения площадок и отдаёт их вместе с признаками свежести, ограниченной или неполной выдачи. Приложение не авторизуется в каждом мини-приложении и не читает ваш Telegram.

Индекс принимает по одному значению модели, фона и узора на запрос. Поэтому выбор нескольких значений разворачивается в комбинации запросов, а ответы объединяются. Fragment и Portals также могут присутствовать в индексе, но их прямые ответы имеют приоритет при совпадении объявления. Приоритет не означает выбор меньшего числа: прямой ответ заменяет индекс как более непосредственный источник, даже если цена выросла.

Индекс может отставать, обновляться или ограничивать число результатов. Приложение сохраняет исходную дату, источник и отметки неполноты. Это не гарантия полного охвата всего рынка или актуальности каждой индексной цены. При изменении разметки Fragment или формата API конкретный обработчик потребуется обновить. Публичный endpoint не объявляется официально стабильным API.

5. Объединение, фильтры и цены

У всех ответов общий формат Offer: идентификатор подарка, коллекция, номер, модель, фон, узор, площадка, сумма, валюта, ссылка, источник и время. Суммы представлены Decimal. Старое обозначение TON в ответах API отображается как GRAM; исходное значение не меняется. Stars сохраняются как Stars.

Каждое объявление заново проходит локальный фильтр, даже если условия уже передавались серверу. Для монохромок проверяется точная тройка коллекция/модель/фон из встроенного списка. Цвет дополнительно ограничивает группу доминирующего цвета модели. Поэтому зелёная модель на синем фоне не проходит от одного совпадения модели или слова Green. Выбор нескольких цветов объединяет их через «или» и пересекается с остальными условиями.

Повторы определяются по площадке и подарку. Один подарок на двух площадках остаётся двумя предложениями с разными ссылками и ценами. Исходная сумма сохраняется; для сравнения разных валют используется общий справочный курс. В стоимость автоматически не добавляются комиссии площадок. Итоговая цена и возможность покупки определяются самой площадкой.

6. Параллельность, страницы и кэш

Одновременно выполняются до четырёх поисковых задач. Внутри страницы Fragment недостающие характеристики могут читаться отдельным пулом до пяти задач. Это уже существующее поведение. Каждый полученный блок передаётся в Qt через сигнал, объединяется с текущими результатами и сохраняется в SQLite. Сортировка применяется ко всему уже загруженному набору.

Только успешный полный обход прямого источника позволяет убрать из соответствующей области старые объявления, которых больше нет. Ошибка, часть страницы или ответ индекса не считаются доказательством продажи и не очищают остальные сохранённые предложения.

Шкала считает законченные поисковые проверки, включая неудачные, и страницы. Один запрос к индексу может представлять сразу несколько площадок; число проверок не обязано равняться шести магазинам. Пока источник сообщает следующую страницу, его обход не завершён. Общее число всех объявлений заранее неизвестно. Поэтому 100% известных проверок не означает доказанный полный охват рынка. Ошибки и неполная выдача отмечаются отдельно.

Широкий цветовой поиск может занять больше времени: например, зелёная группа включает 162 модели в разных коллекциях. Кэш ускоряет повторное открытие, но не делает все цены рынка мгновенно свежими. Остановка прекращает дальнейшую работу по существующему механизму отмены и оставляет полученные предложения. Новых автоматических повторов, лимитов или задержек в версии 0.6 нет.

7. Как собираются изображения

Имена, модели, узоры и палитры берутся из каталога changes.tg. Изображение модели и узора загружается отдельно и используется повторно для разных объявлений. В фоне Qt создаёт QImage: радиальный градиент фона, окрашенные фоновые узоры и прозрачную PNG-модель. Это статическое приближение, а не точная анимация Telegram. Готовые составные картинки кэшируются; в обработчике рисования карточки нет чтения файлов, декодирования PNG или тяжёлого масштабирования. При изменении картинки перерисовываются затронутые видимые карточки.

Цветовой анализ 7806 моделей выполнен при подготовке версии 0.5 и не запускается заново при поиске. Он дал 2589 моделей с 27637 приблизительными сочетаниями. Неоднозначные цветные модели и некоторые контрастные мотивы исключены. Новый выбор цвета в 0.6 использует эти же группы; фотографии и цены заново для этого анализировать не нужно.

Исходный код: providers.py — чтение площадок и обход страниц; catalogue.py и monochrome.py — точные модели и цвета; core.py — общий формат и локальная проверка; cache.py — SQLite; currency.py — пересчёт; previews.py — изображения; ui.py и selectors.py — интерфейс. Эти файлы находятся в папке giftfinder исходного архива.
